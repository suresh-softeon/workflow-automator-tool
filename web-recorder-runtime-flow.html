Workflow Studio - Web Recorder Flow (Code-Level)

This document explains how the Web Recorder works in this application: how launch happens, which methods are called for each button click, where data is stored, and how logging works.

1) App Launch Flow

WorkflowStudioMain.main(...)
-> Application.launch(ApplicationLauncher.class, args)
-> ApplicationLauncher.start(Stage)
-> ApplicationContext.create() (wires repositories/services/executors)
-> StartupCoordinator.startupAsync(...)
-> on success: ApplicationLauncher.showHome()

Key files: WorkflowStudioMain.java, ApplicationLauncher.java, ApplicationContext.java.

2) Navigation to Web Recorder

Home button click
-> ApplicationLauncher.showRecorder()
-> new RecorderView(...).createScene()
-> Theme applied via ThemeManager

Key file: RecorderView.java.

3) Web Recorder UI Action -> Method -> Effect

UI Action Method Call Chain What Happens On Screen / In System
Click + near Project RecorderView.addProjectButton.setOnAction(...) -> ProjectCatalogService.addProject(...) -> JsonProjectCatalogRepository.save(...) Project list updates in Project dropdown and is persisted to catalog JSON.
Click - near Project RecorderView.deleteProjectButton.setOnAction(...) -> ProjectCatalogService.deleteProject(...) -> JsonProjectCatalogRepository.save(...) Selected project/submodules removed from catalog JSON.
Click + near Submodule RecorderView.addSubmoduleButton.setOnAction(...) -> ProjectCatalogService.addSubmodule(...) -> JsonProjectCatalogRepository.save(...) Submodule list refreshes and is persisted.
Click - near Submodule RecorderView.deleteSubmoduleButton.setOnAction(...) -> ProjectCatalogService.deleteSubmodule(...) -> JsonProjectCatalogRepository.save(...) Selected submodule removed and dropdown refreshed.
Click Start Recording RecorderView.start.setOnAction(...) -> WorkflowService.screenExists(...) validation -> RecordingService.startRecording(...) -> PlaywrightCodegenRecorder.startRecording(...) If valid, launches npx playwright codegen --target javascript --output ..., disables Start/Save, enables Stop, and begins writing process output to Recording Console.
Click Stop Recording RecorderView.stop.setOnAction(...) -> RecordingService.stopRecording(...) -> PlaywrightCodegenRecorder.stopRecording(...) Codegen process is stopped, generated temp script is read, script text is loaded into the Generated Script editor, Save button is enabled.
Click Save RecorderView.save.setOnAction(...) -> WorkflowService.saveGeneratedWorkflow(...) -> FileScriptRepository.saveScript(...) + JsonWorkflowRepository.upsert(...) Script is transformed (keep browser open behavior), written to scripts folder, metadata is written to projects.json, success dialog shown.
Click Theme icon RecorderView.themeBtn.setOnAction(...) -> SettingsService.saveTheme(...) -> ThemeManager.applyTheme(...) Theme cycles Dark/Light/System and persists to settings file.

4) Save Operation - Exact Storage Responsibilities

A) Script file write

DefaultWorkflowService.saveGeneratedWorkflow(...) builds relative path: scripts/<project>/<submodule>/<screen>.js

Then FileScriptRepository.saveScript(...):

  • Creates directories if needed.
  • Applies ScriptKeepAliveTransformer.apply(script) (removes close calls and keeps browser open).
  • Writes final JS to disk.

B) Metadata write

DefaultWorkflowService.saveGeneratedWorkflow(...) creates a WorkflowMetadata object and calls JsonWorkflowRepository.upsert(...).

JsonWorkflowRepository persists metadata in: data/projects.json using atomic temp-file move.

C) Project/Submodule catalog

Project/submodule names are maintained in: data/project-catalog.json by JsonProjectCatalogRepository.

D) Theme setting

Theme is saved by JsonSettingsRepository into: settings/theme.json.

5) Where Files Are Stored (Root Path Resolution)

AppPaths.resolve() decides root as:

  1. WORKFLOW_STUDIO_HOME env var (if provided)
  2. Windows: %APPDATA%/Workflow Studio
  3. macOS/Linux: ~/.workflow-studio

Under that root:

  • data/projects.json (workflow metadata)
  • data/project-catalog.json (project/submodule catalog)
  • scripts/.../*.js (saved scripts)
  • settings/theme.json (theme)
  • logs/application.log (application logs)

6) Logging - How and Where

SLF4J + Logback is configured in src/main/resources/logback.xml.

  • Main log file: ${workflow.studio.home}/logs/application.log
  • Rotation file pattern: application_%i.log
  • Roll condition: max size 100MB
  • Root log level: INFO

Runtime examples: PlaywrightCodegenRecorder logs recording start, DefaultWorkflowService logs save/delete, PlaywrightScriptExecutor logs playback start.

7) Playback (Projects Screen) - Short Flow

ProjectsView Play click
-> ExecutionService.executeWorkflow(..., logConsumer)
-> DefaultExecutionService resolves script from projects.json metadata
-> PlaywrightScriptExecutor.start(node script)
-> stdout/stderr streamed to Execution Console ([OUT]/[ERR])
-> completion line with exitCode

8) Error Handling Notes

  • UI validations (missing project/submodule/screen, duplicate screen) are blocked before long-running actions.
  • Storage/process failures throw IllegalStateException and are surfaced via UI error alerts.
  • Console streaming shows process output during recording and playback for easier diagnosis.
